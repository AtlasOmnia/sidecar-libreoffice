# Changelog

All notable changes to Sidecar for LibreOffice are documented here. The format follows Keep a Changelog.

## [0.4.1] - Unreleased

A fix release for the two loopback listeners. No tool, setting, port or protocol changes; the extension keeps its 0.4.0 identifier.

Tested: the unit suite on macOS (Python 3.9, 3.11 and 3.13), in a Linux container (Python 3.11) and on Windows 11 (python.org Python 3.14); on Windows 11 both listeners refused a second socket on their 127.0.0.1 address and port while they listened (with 0.4.0 that bind succeeded) and bound the same port again at once after a close, 20 times each; `hermes plugins validate --install-deps` with Hermes Agent 0.23.1. Not run for 0.4.1: the `.oxt` installed into LibreOffice, the plugin loaded by a Hermes gateway, and another account's socket on Windows.

### Fixed
- **Exclusive ports on Windows.** Both listeners, the extension's bridge on 8660 and the plugin's chat endpoint (8661 when turned on), bind 127.0.0.1 on their port with `SO_EXCLUSIVEADDRUSE` instead of `SO_REUSEADDR`. With `SO_REUSEADDR`, which 0.4.0 used, a second socket could bind the same 127.0.0.1 address and port while the listener ran (seen on Windows 11 for both listeners, with a socket of the same account). That bind is now refused. A bind of the same port number on the wildcard address (`0.0.0.0`) still succeeds; in the same check such a socket did not receive a connection made to 127.0.0.1. macOS and Linux keep `SO_REUSEADDR`, where a second bind of a port in use fails anyway.
- **Unload asks runs to stop first.** When the plugin is disabled or reloaded while a sidebar chat runs, the chat endpoint now asks the runs whose IDs it knows to stop before it shuts its listener down, and wakes the listener's accept loop at once instead of waiting out its 0.5-second poll. Waiting for the listener is bounded by what is left of the 10-second budget, and on Hermes's event loop it does not wait at all. In 0.4.0 the listener shutdown came first and took at least 0.5 seconds of the budget (more while the accept thread was busy) before any stop was sent, and it blocked the event loop for that time; with a short budget a run could be left without a stop request.

### Changed
- Docs: README screenshots of the sidebar in Calc, Writer and Impress (`docs/assets/screenshots/`).

## [0.4.0] - 2026-11-19

First public release. Workflow parity with the Sidecar tools for Microsoft Excel, Word and PowerPoint (baseline `7a565c9`): 55 tools, up from 31. Each change has stale-target checks, a truthful uncertain or partial outcome and an undo contract, and was accepted natively on LibreOffice 26.8.2.2 in disposable profiles. `docs/sidecar-parity.md` maps every Sidecar tool to its LibreOffice counterpart.

Tested: on macOS (LibreOffice 26.8.2.2) and Windows 11 (LibreOffice 26.8.3.1) the 0.4.0 release candidate, still under the extension's earlier identifier, was installed into a disposable profile and exercised through the plugin handlers, with cold restarts and clean quits; on Windows an 18-check plugin-handler matrix covering 25 of the 55 tools, CSV import with one-step undo, wrong-token refusal and a headless start. Freeze panes, protection, tables, sheet activation and recalculation were accepted at the development bridge and called through the plugin handler in the model-driven runs, not in an installed-package matrix. The candidate's unit suite passed on Windows (359 tests then, 16 POSIX-only skips). 29 model-driven scenarios (one run each, through an internal harness with a frontier model configured in its disposable Hermes profile, judged by document readback) together called all 55 tools: 27 passed as recorded, C1 failed only on an over-strict oracle and passes when the same readback is judged with the corrected oracle, and C4 exposed the CSV-import undo defect fixed below; C4's model-driven re-run after the fix passed. See `docs/workflow-acceptance.md`. The release candidate differs from this release in the sidebar's "Hermes is not answering" message, which now names the plugin, in source comments, in the plugin and toolset id (then `libreoffice-live`), and in the renames, security changes and packaging listed below. This release's `.oxt` (stored, SHA-256 in the README) was installed into a new disposable macOS profile through LibreOffice's deployment API and passed the plugin-handler matrix, CSV import with one-step undo, a registration check of the renamed sidebar deck, panel and commands, and a clean quit; it builds with the same SHA-256 on Windows 11, where a command-line `unopkg add` into a disposable profile registered it. Earlier, compressed builds of the same extension files were installed through the Extension Manager dialog on Windows 11 (driven by synthetic window messages on a locked console: the panel in Calc, Writer and Impress in Dark and Light, the pairing token read from the clipboard, the 18-check matrix, CSV import with undo, a cold restart and clean quits) and in an everyday macOS install as an upgrade over the 0.4.0 pre-release, where one real chat from the Calc panel through a Hermes 0.23.1 gateway with a model, with an earlier build of this release's plugin (chat endpoint on by default, before the run-ownership changes below), read, edited and undid a cell, and the panel's tool fence refused a terminal command. Not exercised on Windows: Hermes itself (the plugin has not been installed or loaded by Hermes there; only the LibreOffice extension and the plugin's handlers and unit suite ran), the sidebar chat connected to Hermes, opening the `.oxt` by double-click, **Restart Now** and real mouse and keyboard input. Hermes versions: tested with Hermes Agent 0.23.1 (installed: CLI, plugin manager, one gateway chat); on the v0.23.3 source, run with the 0.23.1 installation's Python environment and without a gateway or model, plugin validation passed with no warnings and the plugin-manager probe (default off, failing polls, unload) gave the same results.

### Security
- **The sidebar chat is off by default.** The plugin setting `chat_port` now defaults to `0`, so the plugin starts no chat endpoint until you set it (8661 is the port the panel calls); with the defaults only the extension's listener on 8660 runs. The panel shows **Bridge unavailable** while the chat is off.
- External-agent model runtimes (for example `codex_app_server`) are unsupported for restricted sidebar chat; keep `chat_port: 0` there. The documented dedicated-profile recipe restricts Hermes tools only, is created without `--clone` (a clone copies model, runtime, persona, memory and secrets), and requires a Hermes-managed model/tool loop configured in that profile.
- The sidebar chat's tool fence also recognises a panel chat by its compression-stable `conversation_id` and by the turn's session context, so a compaction that rotates the session id keeps the fence in Hermes's default API execution mode; the remaining identity gaps are listed in `SECURITY.md`.
- The chat endpoint is owned by the plugin's registration: it starts only after the fence is registered, and disabling or reloading the plugin closes it and asks the runs whose IDs it knows to stop (through the Runs API), also a run whose status poll is still waiting, watching them settle while the fence is still in place within one 10-second budget for its own waiting. Runs that cannot be confirmed stopped are counted and logged as unresolved. A listener without its fence refuses to forward.
- **Accepted limitation (sidebar chat turned on only).** When the plugin is disabled or reloaded, Hermes removes its tool restriction as soon as the unload callback returns; a sidebar chat that was not confirmed stopped keeps running without the restriction, with your full Hermes tools. This is accepted and disclosed for 0.4.0; the fix needs a Hermes-side per-run tool restriction. A gateway shutdown or restart does not unload plugins first: it drains and interrupts its API-server runs (`SECURITY.md`).
- A run the chat endpoint started stays tracked until it is seen to settle. Run creation carries an `Idempotency-Key`, and a lost creation answer is reconciled by resending the same keyed request, never an unkeyed one. A failed or unreadable status poll, or a revoked key, makes the endpoint ask for a stop with the run's own key; a run not confirmed stopped keeps its chat and its slot, and the panel is told that the outcome is not known and not to resend edits blindly. Unknown run states, and a `status` of any other JSON type, are no longer treated as still running, and a stop answer without a known state is not taken as acknowledged.
- Cached secrets are cleared when Hermes reports them removed and on unload; a malformed `API_SERVER_KEY` is refused without being logged; error logs carry the exception class only.
- Both listeners serve at most 16 connections at once (more are refused at once) and give each request one 5-second deadline for headers and body, so a silent or trickling local client cannot pin threads.
- The extension compares the pairing token as bytes (a non-ASCII header is a 401, not a 500), and `bridge.log` carries a fixed route label and status instead of request lines.

### Packaging
- The `.oxt` and the plugin directory carry `LICENSE` and `NOTICE`. `.gitattributes` keeps LF line endings on every platform, so a Windows clone builds the same `.oxt`.
- `scripts/build_oxt.py` stores every member uncompressed and pins the creator system (Unix) besides the fixed timestamps, permissions and order, so the `.oxt` no longer depends on the zlib a Python links (macOS zlib 1.2.12, python.org zlib 1.3.1 and zlib-ng gave three different hashes for identical files) or on the operating system. The expected SHA-256 is read from one place, the README's *Install* section (the plugin README repeats it and a test keeps the two equal); `build_oxt.py --check` and a unit test compare the build with it, and CI runs the check on macOS, Ubuntu and Windows.

### Fixed
- One undo of `calc_import_csv` left the imported cells formatted as Text (`@`): LibreOffice switches a cell to Text when `setString` writes text that would read as a number or formula (`007`, `=1+1`) and does not record that switch for undo (found by model-driven scenario C4). Each imported text cell is now set to Text explicitly first, a change LibreOffice records in the same undo step, so one undo restores content and number formats exactly; imported text cells read back as Text-formatted.
- Windows: a refused panel chat request (wrong token, bad route, oversized body) could reach the panel as "the connection to Hermes was lost" instead of the refusal. The endpoint closed the socket with unread request bytes, and Windows answered with a reset. Refusals now close gracefully: after the reply the endpoint half-closes and discards what the client still sends, bounded to one 0.5 s deadline and about 128 KiB (the last read can add up to 64 KiB; the body is never read first, so a client that declares more than it sends cannot delay the refusal). This also fixes intermittent `test_chat_bridge` failures on Windows.
- `scripts/live_client.py` (development tooling) judged token privacy by POSIX mode bits, which Windows reports as 0o666, so it refused every token there. It now uses the same `private_files` check as the sidebar.
- Closing an Impress deck after `impress_add_text_box`, `impress_find_replace` or `impress_format_text` could abort LibreOffice (SIGABRT in `~SdrObject` on pyuno's GC thread). The bridge's own undo steps held the shapes they change; LibreOffice dropped those steps at close, and the shapes were released only after the document model was gone. The steps now implement `XComponent` and release everything in `dispose()`, which LibreOffice calls when it drops them.
- `calc_get_comments` returned empty text for every comment in a workbook just opened from `.xlsx` (the text is in the file; LibreOffice builds it on demand). It now reads the comment's caption when the cell reports none; the read changes nothing (document not modified, no undo step).
- `calc_format_range` `italic` always failed (`ExecutionUncertain`), and number-format codes were misread in decimal-comma locales (`0.00` showed 1234.5 as `1.235`). Codes are now English notation converted to the document locale.
- The plugin's argument checker rejected union-typed arguments (conditional-format values, filter conditions) and crashed on number arguments without bounds; every number now has bounds and the checker cannot raise.
- Formula conditional formats are anchored at the range's top-left cell (they were evaluated from A1 of the first sheet while reporting `verified`).
- Chart names are unique across the document; sort's automatic revert uses the focused-window undo guard; `undoable` compares the undo stack rather than its top title; table styles, validation readback, protection errors and full-range `if_match` fingerprints are checked before or after writing as appropriate.

### Known limits
- Slide reorder: no identity-preserving API in LibreOffice 26.8 (blocked). Pivot tables deferred; raw OOXML insertion excluded.
- Shape fill and line colours set by `impress_add_shape` are written to `.pptx` as the theme's accent colour.
- Protection does not block the bridge's own writes. `bridge.log` is outside the owner-only file guarantee.

Edge newlines are dropped and inner newlines start further paragraphs; an empty document gets no leading empty paragraph. Live: appended at the end and at the start, each insert was its own paragraph (1 → 2 paragraphs) and one undo restored the original paragraphs exactly (no empty paragraph).

### Fixed
- An invalid cell address sent straight to the bridge was answered as an unhandled failure (HTTP 500), which the plugin client reports as `ExecutionUncertain` for a change. It is now `Validation` with `state: not_started`. The plugin already rejected such addresses before sending.
- A paragraph-mode Writer insert no longer leaves the new text after an already-empty last paragraph (or before an already-empty first one): the bridge fills that empty paragraph in place and adds a break only when the edge paragraph holds text. Undo restores the original paragraphs, including the empty one.
- Bridge undo on a background document intermittently returned `Timeout`/`not_started` after about 8 s. Live diagnosis on macOS (LibreOffice 26.8.2.2): with LibreOffice hidden, the undo timed out in 21 of 30 loop iterations. During the stall the queued main-thread call sat unstarted while LibreOffice's main thread slept in `nextEventMatchingMask` (`sample`), and any later post released it at once. The best-supported reading of `AquaSalInstance::DoYield` is a lost event-loop wakeup between consecutive posts; the undo path posts its main-thread calls back to back. Visible windows mask it because caret and repaint timers wake the loop. While a call has not started, the bridge now re-posts a no-op wakeup every 0.2 s, within the same 8 s budget, and logs how many were needed. After the fix, 40 of 40 hidden iterations (max 0.70 s) and 30 of 30 visible ones (max 0.54 s) were clean.
- **Tools → Copy Hermes pairing token** (now **Copy Sidecar pairing token**) aborted LibreOffice. The token was copied, but looking up the message-box type as a constant (it is a UNO enum) raised an exception into LibreOffice's event loop, and soffice aborted with SIGABRT. The handler now never lets an exception escape. It parents the notice on the current document window and logs failures without the token.
- `write_formula` in `calc_execute_plan` writes to the cell; it failed live with `AttributeError: setFormula` on the one-cell range object and was reported as `ExecutionUncertain`.
- **Tools → Copy Hermes pairing token** now appears: the merge properties sit in a merge-instruction node (`S1`) and target `.uno:ToolsMenu\.uno:ExtensionManager`. The old layout put the properties directly under the extension node with a bare `.uno:ToolsMenu` merge point, and LibreOffice 26.8 silently dropped the item.
- The internal E2E harness refuses proxy runtimes, passes its credential through the child environment only, drops inherited live-session variables, redacts traces before they reach disk, bounds the chat with `--max-turns`/`--run-budget`, and fails if the credential is found in any file under the disposable home or work directory.

### Fixed
- `calc_execute_plan` now follows the WorkbookPlan V1 shapes more strictly: `sentinel_unchanged` uses `{sheet, address, expected}` for one cell, plan text fields enforce the V1 length limits, and a contract test pins the supported kinds as a subset of V1 (`clear_range` is a documented LibreOffice extension).
- The plugin client never downgrades an unknown mutation outcome: lost connections, undecodable or oversize replies, uncategorized 5xx and data-less successes after a mutation was sent are `ExecutionUncertain`; only explicit `not_started` replies stay `Timeout`/`Unavailable`. `Protocol` and `Capacity` are now reported instead of being folded into `Validation`.
- A main-thread call that times out before LibreOffice starts it is now cancelled atomically, so a mutation reported as `Timeout` (`state: not_started`) can never run later.
- Mutations report `ExecutionUncertain` only after their first document change begins; earlier failures keep `Validation`, `NotFound`, `Stale` or `Unavailable`, and errors after a write begins are never downgraded to `Validation`.

### Known limits
- The macOS build supports Python-UNO only in-process; standalone Python-UNO and remote-UNO shell clients are unsupported.
- The bridge is local-only and defaults to authenticated loopback port 8660.
